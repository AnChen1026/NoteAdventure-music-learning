# NoteAdventure｜啟動說明

本機有兩種開法；線上展示部署在 Railway（見第三節）：

- **方式一：Docker（建議）**：一個指令啟動 MySQL + Flask + Vue，不用自己裝 Python、Node、MySQL。
- **方式二：本機直接執行**：開發、改程式時使用。

前端為 Vue 3（`frontend/`），老師與學生共用同一個 Vue 專案與同一套 Flask API。

| 角色 | 介面 | 入口 |
|------|------|------|
| 學生 | Vue 一頁版（16:9 舞台） | `http://localhost:5000/student` |
| 老師 | Vue 管理後台 | `http://localhost:5000/teacher` |

---

## 一、Docker 開啟（建議）

需要：Docker Desktop。

### 1. 啟動

在專案根目錄：

```bash
docker compose up -d --build
```

第一次會下載映像檔並打包前端，約需幾分鐘。完成後開啟：

- 學生：`http://localhost:5000/student`
- 老師：`http://localhost:5000/teacher`（第一次請先在「老師註冊」建立帳號）
- 自測：`http://localhost:5000/api/health`

### 2. 包含的服務

| 服務 | 內容 |
|------|------|
| `db` | MySQL 8.0；第一次啟動時自動執行 `backend/sql/music_rpg_schema_v2.sql` 建表 |
| `app` | Flask（gunicorn）＋打包好的 Vue 前端＋素材，對外開 `5000` |

資料保存在 Docker volume，關掉容器不會遺失：

| Volume | 內容 |
|--------|------|
| `db_data` | 資料庫 |
| `uploads` | 學生上傳的練習錄音 |
| `cache` | 兩廳院節目快取 |

時區已設為 `Asia/Taipei`（任務期限、上傳時間為台灣時間）。

### 3. 常用指令

```bash
docker compose ps
```

```bash
docker compose logs -f app
```

```bash
docker compose down
```

改了程式碼後重新打包並啟動：

```bash
docker compose up -d --build
```

清空所有資料（資料庫、錄音、快取）重新開始，**無法復原**：

```bash
docker compose down -v
```

### 4. 帳密與連接埠（可選）

不設定也能直接用。若要修改，把 `.env.example` 複製成 `.env`（不會進 Git）再改：

| 變數 | 說明 |
|------|------|
| `MYSQL_ROOT_PASSWORD` | 容器內 MySQL root 密碼 |
| `MYSQL_USER`、`MYSQL_PASSWORD` | Flask 連資料庫用的帳號 |
| `NOTEADVENTURE_SECRET_KEY` | 登入 cookie 的密鑰，建議改成長隨機字串 |
| `APP_PORT` | 對外連接埠，預設 `5000`（被占用時可改成 `8000` 等） |

> 資料庫帳密只在**第一次建立 `db_data` 時**生效；之後要改，需 `docker compose down -v` 重建。

容器內的 MySQL 不對外開連接埠，不會和本機的 MySQL（3306）衝突。

## 二、本機直接執行（開發用）

### 1. 環境準備

需要：Python 3.11+、Node.js 18+、MySQL 8。

Windows：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

macOS / Linux：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. 資料庫

1. 建立 MySQL 資料庫（建議名稱 `music_rpg_v2`）
2. 選定該資料庫後執行 `backend/sql/music_rpg_schema_v2.sql`（只建表與寵物階段，不含 `CREATE DATABASE`）
3. 在專案根目錄建立 `config.ini`（**不要提交到 Git**）：

```ini
[DB]
host=localhost
user=root
password=your_password
port=3306
database=music_rpg_v2
```

也可以用環境變數 `NOTEADVENTURE_DB_HOST`／`_PORT`／`_USER`／`_PASSWORD`／`_NAME` 取代（優先於 `config.ini`）。

### 3. 打包 Vue 前端

```bash
cd frontend
npm install
npm run build
cd ..
```

打包結果在 `frontend/dist/`，由 Flask 直接提供。

### 4. 啟動 Flask

```bash
flask --app backend/app.py run --port 5000
```

開啟 `http://127.0.0.1:5000/student` 或 `/teacher`。

### 5. 開發前端時（可即時看到修改）

Flask 保持開著，另開一個終端機：

```bash
cd frontend
npm run dev
```

改開 `http://localhost:5173/student` 或 `/teacher`；`/api` 與 `/assets` 會自動轉給 Flask（:5000）。

架構：

```text
瀏覽器 ──→ Flask（:5000）──┬─ frontend/dist（Vue 頁面）
                           ├─ /api/...（backend/api → backend/services → MySQL）
                           └─ /assets/material/...（素材）
```

### 6. 自動化測試

```bash
pip install -r requirements-dev.txt
pytest
```

- 讀取 `config.ini` 的連線資訊，但只使用 **`<資料庫名稱>_test`**（例如 `music_rpg_v2_test`），每次測試都會刪除重建；正式資料庫不會被動到。
- 上傳的測試音檔寫到暫存資料夾，不會留在 `uploads/`。
- `tests/test_api_flow.py`：依期中展示流程跑完整 API（老師／學生／任務／上傳發獎／寵物／商店／兌換／權限）。
- `tests/test_pages.py`：Vue 各路徑、打包的 JS／CSS 與素材都能正常載入（需先 `npm run build`）。
- `tests/test_schema.py`：`backend/sql/music_rpg_schema_v2.sql` 在空資料庫上能完整執行。
- `tests/test_reward_concurrency.py`：兩個請求同時發獎時只會成功一次。
- `tests/test_demo.py`：自動建表、示範資料與示範帳號保護。

push 到 GitHub 後，GitHub Actions（`.github/workflows/test.yml`）會自動打包前端並執行全部測試。

## 三、Railway 部署（線上展示）

設定檔：`railway.toml`（使用 `Dockerfile` 建置，健康檢查 `/api/health`）。
容器啟動時會先執行 `backend/init_db.py`：資料庫是空的就自動建表，`NOTEADVENTURE_DEMO=1` 時建立示範資料。

1. Railway 新增 Project → **Deploy from GitHub repo** 選這個 repo。
2. 同一個 Project 內 **New → Database → MySQL**。
3. 在 app 服務的 **Variables** 加入（`${{MySQL.…}}` 會自動帶入資料庫連線）：

   | 變數 | 值 |
   |------|------|
   | `NOTEADVENTURE_DB_HOST` | `${{MySQL.MYSQLHOST}}` |
   | `NOTEADVENTURE_DB_PORT` | `${{MySQL.MYSQLPORT}}` |
   | `NOTEADVENTURE_DB_USER` | `${{MySQL.MYSQLUSER}}` |
   | `NOTEADVENTURE_DB_PASSWORD` | `${{MySQL.MYSQLPASSWORD}}` |
   | `NOTEADVENTURE_DB_NAME` | `${{MySQL.MYSQLDATABASE}}` |
   | `NOTEADVENTURE_SECRET_KEY` | 一段長隨機字串 |
   | `NOTEADVENTURE_COOKIE_SECURE` | `1` |
   | `NOTEADVENTURE_DEMO` | `1` |
   | `TZ` | `Asia/Taipei` |
   | `RAILWAY_RUN_UID` | `0`（讓容器能寫入 volume） |

4. app 服務 **Settings → Deploy** 的 **Custom Start Command** 保持空白，讓 Dockerfile 的啟動指令（先建表再啟動 gunicorn）生效。
5. app 服務 **Settings → Volumes** 新增 volume，掛載路徑 `/app/uploads`（保存錄音）。
6. **Settings → Networking → Generate Domain** 產生網址。
7. 開 `https://<網址>/api/health` 確認服務正常，再用示範帳號登入。
8. 在 **Workspace → Usage** 設定用量上限，避免超出預算。

示範帳號：老師 `demo@noteadventure.app`、學生 `demo_student`，密碼都是 `demo1234`；示範帳號不能修改或重設密碼，每次重新部署都會把密碼重設回來。

之後只要 push 到 `main`，Railway 就會自動重新建置與部署。

> Railway 將於 2026-12-01 停止支援 `railway.toml`；之後請在 app 服務的 Settings 手動設定 Healthcheck Path 為 `/api/health`（Dockerfile 會自動偵測）。

## 常見問題

**錄音檔存在哪？**
Docker：`uploads` volume。本機執行：專案根目錄的 `uploads/audio/`（不進 Git）。

**雲端時間差 8 小時？**
雲端 MySQL 預設 UTC。`backend/db.py` 每次連線都會把資料庫時區設成與 Flask 相同（`TZ`），所以 `TZ` 必須設好。

**手機能不能連？**
同一個 Wi-Fi 下可用電腦的區網 IP（例如 `http://192.168.x.x:5000/student`）開啟；但瀏覽器只允許在 HTTPS 或 localhost 使用麥克風，所以手機上的琴房錄音無法使用。

**5000 連接埠被占用？**
Docker：在 `.env` 設 `APP_PORT=8000`。本機：`flask --app backend/app.py run --port 8000`。
